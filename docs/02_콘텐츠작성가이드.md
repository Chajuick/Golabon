# 골라본 콘텐츠 작성 가이드

> 리뷰 1건을 추가하는 전체 워크플로. 개발 지식 없이도 따라 할 수 있게 정리했습니다.
> 원본 리뷰·사진(예: 네이버 인플루언서 자료) → 이 양식에 채우기 → 빌드 → 발행.

---

## 0. 한눈에 보는 흐름

```
1. lib/data.js 의 products[] 에 객체 1개 추가  (텍스트)
2. public/reviews/<id>/ 에 사진 넣고 photos 로 연결   (사진)
3. prices/channels 에 실제 제휴 링크(url) 연결        (수익)
4. npm run build → 발행
```

모든 콘텐츠는 **`lib/data.js` 한 파일**에 모입니다. 다른 파일은 건드릴 필요 없습니다.

---

## 1. 리뷰 추가 (텍스트)

`lib/data.js` 의 `const products = [ ... ]` 배열 안에 아래 템플릿을 복사해 채웁니다.

### 📦 제품(product) 템플릿

```js
{
  id: 'unique-slug',              // URL이 됨: /p/unique-slug/ (영문-소문자-하이픈, 중복 금지)
  type: 'product',
  name: '제품 이름',
  cat: 'shopping',                // shopping/fashion (카테고리 키, 아래 표 참고)
  catLabel: '생활용품 · 주방',     // 화면 표시용 라벨
  img: 'linear-gradient(135deg,#EAF1EF,#D7E6E1)', // 사진 없을 때 카드 배경(아무 그라데이션)
  oneLiner: '카드에 뜨는 한 줄 소개',
  verdict: 'rec',                 // rec(추천) | cond(조건부) | no(비추천)
  badges: ['used', 'value'],      // used 직접써봄 / fast 빠른배송 / value 가성비
  usedDays: 21,                   // 직접 사용한 일수
  rating: 4.6,                    // 0~5
  views: 0,                       // 조회수(표시용, 0부터)
  reBuy: '있음',                  // 재구매 의향
  verifyDate: '2026.06.03',       // 검증일
  pros: ['좋은 점 1', '좋은 점 2'],
  cons: ['아쉬운 점 1'],           // ⚠ 최소 1개 필수 (단점 없는 리뷰는 발행 안 함)
  priceFrom: 7800,                // 최저가 시작값(숫자)
  prices: [
    { brand: 'coupang', price: 13500, note: '로켓배송 · 내일 도착', tag: 'fast', url: '' },
    { brand: 'ali',     price: 8400,  note: '7~12일',             tag: '',     url: '' },
    { brand: 'temu',    price: 7800,  note: '9~15일 · 최저가',     tag: 'value', url: '' },
  ],
  summary: {                      // 검증 요약(상세 표/요약카드). 키:값 자유롭게 5개 내외
    '직접 사용': '21일', '두께': '2.5mm', '마감 품질': '좋음', '냄새/오염': '초기 약간', '배송 만족도': '좋음',
  },
  recFor: '이런 사람에게 추천하는 한 문장',
  noFor: '이런 사람에겐 비추천하는 한 문장',
  verdictLine: '한 줄 판정. 이 문장이 검색결과 설명(meta description)으로도 쓰임.',
  body: {
    why: '왜 이 제품을 골랐는가',
    ctx: '배송·포장 상태',
    exp: '실제 사용 후기 (가장 긴 본문)',
    good: '좋았던 점 요약',
    bad: '아쉬웠던 점 요약',
  },
  // photos: { ... }              // 사진 연결(2번 참고). 없으면 안내 placeholder가 뜸
  // altId: 'other-slug',         // 비추천일 때 대체 추천템 id (선택)
},
```

### 📍 장소(place) 템플릿 — 맛집·카페·숙소·놀거리·뷰티

제품과 다른 부분만 표기 (`usedDays/reBuy/priceFrom/prices` → 아래로 교체):

```js
{
  id: 'place-slug', type: 'place', name: '장소 이름',
  cat: 'food', catLabel: '맛집 · 한식', img: 'linear-gradient(...)',
  oneLiner: '...', verdict: 'rec', badges: ['visited', 'value'],
  rating: 4.5, views: 0,
  area: '서울 · 연남동',          // 위치
  visit: '직접 방문 2회',         // 방문 횟수
  priceRange: '1인 9,000원대',    // 가격대(상세). 풀버전 — '한눈에 보는 장소 정보' 표에 그대로 노출
  priceShort: '9,000원대~',       // (선택) 카드·헤더·요약용 대표 가격. 생략 시 priceRange로 폴백
  revisit: '있음',               // 재방문 의향
  verifyDate: '2026.06.03',
  pros: ['...'], cons: ['...'],
  channels: [                     // 예약·정보 채널 (제품의 prices 대신)
    { brand: 'naver',      note: '지도 · 방문자 리뷰 4.4', cta: '네이버에서 보기', url: '' },
    { brand: 'catchtable', note: '대기 등록 가능',         cta: '캐치테이블 대기', url: '' },
  ],
  summary: { '직접 방문': '2회', '웨이팅': '점심 20분+', /* ... */ },
  recFor: '...', noFor: '...', verdictLine: '...',
  body: { why:'...', ctx:'위치·접근성·첫인상', exp:'실제 방문 후기', good:'...', bad:'...' },
},
```

### 카테고리 키 (cat)
| 키 | 라벨 |
|---|---|
| `shopping` | 생활용품 |
| `fashion` | 패션 |
| `food` | 맛집 |
| `cafe` | 카페 |
| `play` | 놀거리 |
| `stay` | 숙소 |
| `beauty` | 뷰티 |

### 브랜드/채널 키 (prices.brand / channels.brand)
`coupang`(쿠팡) `ali`(알리) `temu`(테무) `musinsa`(무신사) `zigzag`(지그재그)
`naver`(네이버) `catchtable`(캐치테이블) `instagram`(인스타) `yanolja`(야놀자)
`yeogi`(여기어때) `airbnb`(에어비앤비) `kakao`(카카오)
→ 새 브랜드는 `lib/data.js`의 `brands`에 `{ name, color, short }`로 추가하면 됩니다.

## 2. 사진 연결 (인플루언서 제공컷)

1. `public/reviews/<id>/` 폴더를 만들고 사진을 넣습니다. (예: `public/reviews/silicone-mat/lead.jpg`)
2. 해당 제품 객체에 `photos`를 추가합니다:

```js
photos: {
  g0:   '/reviews/silicone-mat/main.jpg',   // 상단 대표 이미지(정사각)
  g1:   '/reviews/silicone-mat/thumb1.jpg', // 썸네일 g1~g4 (선택)
  lead: '/reviews/silicone-mat/lead.jpg',   // 상세컷 대표(가로 와이드)
  p0:   '/reviews/silicone-mat/point1.jpg', // "이 점을 보세요" 디테일컷 1
  p1:   '/reviews/silicone-mat/point2.jpg', // 디테일컷 2
  use:  '/reviews/silicone-mat/usage.jpg',  // "실제로 써보면" 사용컷
},
```

- 경로는 항상 `/reviews/...`로 시작 (앞에 `public` 안 붙임).
- 넣지 않은 슬롯은 자동으로 안내 placeholder가 표시되므로, 가진 사진만 채워도 됩니다.
- ⚠ **사진은 제공 동의를 받은 자료만.** 출처는 상세페이지 하단에 자동 표기됩니다.

> ✅ 검증됨: `photos`/`url`을 넣고 `npm run build` 하면 정적 HTML에 실제 `<img>`와 제휴 `<a>`가 그대로 생성됩니다.

---

## 3. 제휴 링크 연결 (수익)

`prices[].url`(제품) 또는 `channels[].url`(장소)에 **실제 제휴 트래킹 링크**를 넣습니다.

```js
{ brand: 'coupang', price: 13500, note: '...', tag: 'fast', url: 'https://link.coupang.com/a/XXXXXX' },
```

- `url`이 비어 있으면 클릭 시 "준비 중" 안내가 뜨고, 채워지면 새 탭으로 이동합니다.
- 모든 제휴 링크는 자동으로 `rel="sponsored nofollow noopener"`가 붙습니다 (검색엔진 가이드·약관 준수).
- ⚠ 쿠팡 파트너스 등 각 프로그램의 링크 생성 규칙·고지 의무를 반드시 확인하세요 (→ `docs/01_기획설계서.md` 8장 체크리스트).

---

## 4. 발행

```bash
npm run dev      # 로컬에서 미리보기 (http://localhost:3000)
npm run build    # out/ 에 정적 HTML 생성 → 호스팅에 업로드
```

새 리뷰는 자동으로 홈/카테고리/탈락리스트(해당 시)/사이트맵에 반영됩니다.

---

## 5. 발행 전 체크리스트

- [ ] `id`가 기존과 중복되지 않는가
- [ ] `cons`(단점)가 1개 이상 있는가
- [ ] `verdict`와 `verdictLine`이 일치하는가
- [ ] `recFor`/`noFor`를 적었는가
- [ ] 사진 제공 동의를 받았는가 / 출처가 명확한가
- [ ] 제휴 링크가 올바른 트래킹 링크인가
- [ ] 비추천(`no`)이면 `altId`로 대체템을 제시했는가 (선택이지만 권장)
- [ ] `npm run build`가 에러 없이 끝나는가
