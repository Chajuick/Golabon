# 골라본(Golabon) 기획·설계서

> 직접 써보고 가본 것만 골라본. — 검증된 리뷰 큐레이션 + 제휴 커머스
> 작성 기준일: 2026-06-03 · 기준 산출물: `골라본 (오프라인).html` 프로토타입 분석

---

## 0. 이 문서의 목적

말로 설명한 사업모델과, 이미 만들어진 프로토타입(홈/상세/카테고리/탈락리스트)을 하나의 기준으로 정렬한다.
이후 단계(개발 → 콘텐츠 입력 → 실행 점검)가 이 문서를 기준점으로 진행된다.

---

## 1. 한 줄 정의 & 포지셔닝

- **한 줄 정의:** 믿을 수 있는 인플루언서·블로거의 리뷰를 **자체 품질 검토**한 뒤, 쇼핑몰 상품상세 UX로 재구성해 보여주고, 사용자가 외부 구매·예약 링크로 이동하면 **제휴 수수료**를 받는 큐레이션 미디어.
- **시장 맥락:** 블로그·인스타에 무분별한 협찬/AI 저품질 광고가 범람 → "이거 진짜 괜찮은 거 맞아?"라는 신뢰 피로감.
- **포지션:** *광고처럼 안 보이는 광고*가 아니라, **검증을 전면에 내세운 신뢰 미디어**.
  - 핵심 메시지: "협찬 아님 / 직접 써보고 가봄 / **비추천(탈락)도 솔직하게 한다**"

### 경쟁 대비 차별점(해자)
| 구분 | 일반 체험단·파워블로그 | 일반 가격비교(다나와 등) | **골라본** |
|---|---|---|---|
| 콘텐츠 출처 | 협찬/대가성 | 스펙·가격 데이터 | 실사용·실방문 검증 |
| 비추천 | 거의 안 함(돈 끊김) | 안 함 | **탈락 리스트를 전면에** |
| 톤 | 광고체 | 무미건조 | 솔직한 1인칭 검증 |
| 수익 | 원고료 | 제휴/광고 | 제휴 + 신뢰 자산 |

> ⭐ **"거르는 것도 추천이다"** = 구조적으로 경쟁자가 따라 하기 어려운 차별점. 프로토타입의 `골라본 탈락 리스트` 섹션이 정확히 이 역할.

## 2. 수익 모델

1. **제휴 커머스(메인):** 쿠팡파트너스 / 알리 / 테무 / (패션) 무신사·지그재그 / (예약) 야놀자·여기어때·캐치테이블 등 링크 클릭→전환 수수료.
   - 제품(product)이 수익화가 즉시 가능 → **초기 집중 영역**.
   - 장소(place)는 제휴 단가가 얇거나 프로그램이 제한적 → 신뢰·트래픽 확보용으로 운영, 수익은 후순위.
2. **(확장) 브랜드 검증 의뢰:** 검증 기준을 자산화한 뒤, "골라본 검증 통과" 형태의 유료 검증(단, 추천 여부는 매수 불가 — 신뢰 유지가 전제).
3. **(확장) 자체 셀렉션/공동구매:** 검증템을 묶은 큐레이션 커머스.

> ⚠️ 1번 외에는 트래픽이 쌓인 뒤의 옵션. 초기엔 **제품 제휴 단일 수익**으로 단순화.

## 3. 타깃 & 콘텐츠 도메인

- **1차 타깃:** 20~30대, 자취/신혼/1인가구. "광고 말고 진짜 후기"를 찾는 검색 사용자.
- **도메인(프로토타입 카테고리 그대로):** 생활용품 · 패션 · 맛집 · 카페 · 놀거리 · 숙소 · 뷰티.
- **초기 전략:** 여자친구(네이버 인플루언서)의 **기존 검증 자산이 두꺼운 1~2개 카테고리부터** 깊게 채운다(넓게 얕게 X). 추천 후보: 생활용품 + 맛집/카페.

## 4. 콘텐츠 운영 원칙 (편집 정책)

프로토타입이 이미 강제하는 규칙을 명문화한다:

1. **직접 사거나 가본 것만 다룬다.** 협찬·초대 콘텐츠는 골라본 본문으로 쓰지 않는다.
2. **충분히 겪는다.** 제품은 일정 기간 사용(`usedDays`), 장소는 실제 방문(`visit`) 후 작성.
3. **장점과 단점을 함께 기록한다.** 단점 0개 리뷰는 발행하지 않는다(`cons` 필수).
4. **판정을 명시한다.** `추천 / 조건부 추천 / 비추천` 중 하나 + 한 줄 판정(`verdictLine`).
5. **누구에게 맞고 안 맞는지 적는다.** (`recFor` / `noFor`)
6. **제휴 고지를 숨기지 않는다.** 모든 상세·푸터에 고지문 노출(이미 구현됨).
7. **사진 출처를 표기한다.** 인플루언서/블로거 제공 또는 직접 촬영. 무단 도용·재배포 금지.

## 5. 데이터 스키마 (실제 코드 `GOLABON_DATA` 기준)

콘텐츠 1건 = `products[]` 배열의 객체 1개. 타입은 `product`(물건) 또는 `place`(장소·서비스).

### 공통 필드
| 필드 | 설명 | 예시 |
|---|---|---|
| `id` | 고유 슬러그(URL용) | `'silicone-mat'` |
| `type` | `'product'` \| `'place'` | `'product'` |
| `name` | 이름 | `'실리콘 주방 매트'` |
| `cat` / `catLabel` | 카테고리 키 / 표시 라벨 | `'shopping'` / `'생활용품 · 주방'` |
| `oneLiner` | 카드용 한 줄 소개 | `'기름·물 튐 막아주는…'` |
| `verdict` | `'rec'`(추천)\|`'cond'`(조건부)\|`'no'`(비추천) | `'rec'` |
| `badges` | `used`/`visited`/`fast`/`value` 배열 | `['used','fast']` |
| `rating` | 평점(0~5) | `4.6` |
| `views` | 조회수(표시용) | `9210` |
| `pros` / `cons` | 좋은 점 / 아쉬운 점 배열(**cons 필수**) | `['…']` |
| `summary` | 검증 요약 키:값(상세 표·요약카드) | `{ '직접 사용':'21일', … }` |
| `recFor` / `noFor` | 추천 대상 / 비추천 대상 | `'…'` |
| `verdictLine` | 한 줄 판정 | `'3주 써보니…'` |
| `body` | `{ why, ctx, exp, good, bad }` 본문 5블록 | — |
| `verifyDate` | 검증일 | `'2026.05.18'` |
| `altId` | (선택) 비추천 시 대체템 id | `'yeonnam-noodle'` |

### 제품(product) 전용
| 필드 | 설명 |
|---|---|
| `usedDays` | 직접 사용 일수 |
| `reBuy` | 재구매 의향 |
| `priceFrom` | 최저가 시작값 |
| `prices[]` | `{ brand, price, note, tag }` 채널별 가격 (`tag`: `fast`/`value`) |

### 장소(place) 전용
| 필드 | 설명 |
|---|---|
| `area` | 위치 (`'서울 · 연남동'`) |
| `visit` | 방문 횟수 (`'직접 방문 2회'`) |
| `priceRange` | 가격대 풀버전 (`'음료 9,500원~ · 빵 4,300원대'`) — 상세 표에 노출 |
| `priceShort` | (선택) 카드·헤더·요약용 대표 가격 (`'4,300원대~'`) — 생략 시 `priceRange`로 폴백 |
| `revisit` | 재방문 의향 |
| `channels[]` | `{ brand, note, cta }` 예약·정보 채널 |

### 사진 슬롯
상세페이지 이미지 영역은 `image-slot` 컴포넌트(`gb-{id}-lead`, `-g0~g4`, `-p0/p1`, `-use`)에 사진을 끌어다 놓으면 채워지는 구조. 텍스트(데이터)와 사진(슬롯)이 분리돼 있어 운영이 편하다.

## 6. 유저 플로우 (방문자 여정)

```
[유입]  네이버 검색 / 여친 채널 링크 / SNS / 직접
   │
   ▼
[홈]  Hero(오늘의 검증) → 신뢰지표 → 추천 카드섹션 → 탈락리스트 → 검증 프로세스
   │  └ "비추천 먼저 보기" 동선으로 신뢰 형성
   ▼
[탐색]  카테고리/검색으로 관심 제품·장소 필터
   │
   ▼
[상세=리뷰]  갤러리 → 한 줄 판정 → 검증요약(추천/비추천 대상)
   │         → 상세컷(인플루언서 사진) → pros/cons → 본문 5블록 → 대체템
   │
   ▼
[신뢰 형성]  "솔직하다"는 인식 → 구매 의사결정
   │
   ▼
[외부 전환]  구매처 비교 카드 / 예약 채널 → 제휴 링크 클릭 → 외부 사이트
   │         (골라본은 직접 결제·예약 안 함 — 고지)
   ▼
[수익]  외부에서 전환 발생 → 제휴 수수료
```

**설계 보강 포인트(현재 프로토타입에 약한 곳):**
- 유입 진입점이 **상세페이지(=검색 랜딩)**가 될 가능성이 높음 → 상세 단독으로도 신뢰·전환이 완결되게(현재 잘 돼 있음).
- 상세 → 관련/대체템 → 다른 상세로 이어지는 **회유 동선**(이미 `related`, `altId` 있음) 강화.
- 찜(좋아요)·검색은 현재 로컬 상태만 → 추후 실제 기능화 여부 결정.

## 7. 운영자 워크플로우 (여친 리뷰 → 발행 파이프라인)

```
1. 소스 수집     여친 네이버/블로그/인스타의 기존 리뷰·사진 확보 (+제공 동의)
       │
2. 검증 판정     실사용/실방문 사실 확인 → verdict 결정(추천/조건부/비추천)
       │         단점 최소 1개 도출, recFor/noFor 정의
       │
3. 데이터 입력   스키마(5장)에 맞춰 products[] 객체 1건 작성
       │         · oneLiner / verdictLine / pros / cons / summary / body
       │         · 제품이면 prices[], 장소면 channels[]
       │
4. 사진 배치     image-slot에 제공 사진 드래그(대표/디테일/사용컷)
       │         · 출처 표기, 도용 금지 확인
       │
5. 제휴 링크     각 channel/price의 cta를 실제 제휴 링크로 연결
       │         · 쿠팡파트너스 등 트래킹 코드 포함
       │
6. 발행/검수     반응형·링크·고지문 확인 → 공개
       │
7. 유입 연결     여친 채널에서 골라본 상세로 유도(상호 트래픽)
```

> 이 파이프라인을 **입력 양식(템플릿)**으로 만드는 게 3단계 "콘텐츠 입력 워크플로" 작업의 목표.

## 8. 법·약관 체크리스트 (출시 전 필수)

- [ ] **공정위 「추천·보증 등에 관한 표시·광고 심사지침」**: 제휴(대가성) 사실을 명확·근접·식별 가능하게 고지 — *이미 푸터/상세에 구현됨*. 문구·위치 최종 점검.
- [ ] **쿠팡파트너스/알리/테무 등 각 제휴 프로그램 약관**: 자체 사이트 운영 허용 범위, 금지 표현, 가격 표기 규칙, 트래킹 링크 사용 조건 확인.
- [ ] **사진 저작권·초상권**: 여친/블로거 제공 사진의 사용 범위 서면 동의. 제3자 도용 자료 금지.
- [ ] **이해상충/중복 콘텐츠**: 여친 네이버 채널과 골라본 간 동일 콘텐츠의 중복 게시·SEO 페널티·채널 정책 위반 여부 점검.
- [ ] **개인정보/쿠키**: 찜·분석 도입 시 처리방침 고지.
- [ ] **사업자/세무**: 제휴 수익 발생 시 사업자 등록·소득 신고.

## 9. SEO / 유입 전략 (사업의 9할)

> 예쁜 카탈로그가 있어도 **유입이 없으면 수수료는 0**. 디자인보다 여기가 본질.

1. **검색 친화 구조:** 상세=독립 URL, 의미 있는 제목/메타, 구조화 데이터(Review/Product schema.org), OG 태그. → 개발 단계에서 정적 생성(SSG) 우선.
2. **여친 채널 레버리지:** 기존 네이버 인플루언서 트래픽을 골라본으로 유도(채널 정책 위반 안 되는 선에서). 콜드스타트 해결의 핵심.
3. **롱테일 키워드:** "OO 실사용 후기", "OO 단점", "OO vs OO"처럼 **비교·단점 검색**을 노린 콘텐츠가 골라본의 톤과 정확히 맞음.
4. **비추천 콘텐츠의 역설적 흡입력:** "OO 광고 실제로 가보니" 류는 클릭률·체류시간이 높음 → 신뢰 + 트래픽 동시 확보.

### 부록 A. 추출된 원본 소스 (편집용)
원본 `골라본 (오프라인).html`은 디자인 툴 단일 번들이라 직접 수정이 어려움. 분석 과정에서 아래로 풀어둠:
